## A 批：历史加载（你的主需求）

### A1. 菜单栏内存加载 100 → 50
**文件**：`Clipboard/ClipboardManager.swift:325`
`menuHistoryLimit` 改为 `min(historyLoadCount, 50)`。
- 菜单栏本来就只渲染前 50（`MenuController.menuDisplayLimit=50`），加载 100 是浪费。
- 不影响搜索窗口翻页（它直接读 `historyLoadCount` 当 pageSize）。
- `ensureMenuSummariesLoaded`/`refreshFromPasteboardIfNeeded`/`reloadLoadedSummaries`/启动预热都走 `menuHistoryLimit`，自动跟着降到 50。
- 菜单关闭时 `menuDidClose` 已经调 `releaseMenuMemory()` 清空 `recentSummaries`——符合「点开菜单才加载、关掉就清」。

### A2. 历史管理器（搜索窗口）打开即加载全部
**文件**：`UI/SearchView.swift:31-32, 60-61`
- `init()` 和 `onAppear()` 里 `browseLimit` 初值从 `historyLoadCount`(100) 改为 `ClipboardManager.shared.totalHistoryCount`（全部）。
- 确认 `totalHistoryCount` 在搜索窗口打开前已就绪（`ensureMenuSummariesLoaded`/`refreshFromPasteboardIfNeeded` 会先设它；若没拉过则搜索窗口 onAppear 时现查一次 `repository.count()`）。
- 列表用 `Table(viewModel.results)` 懒渲染（`SearchView.swift:465`），即使几千条也不卡。
- 关闭清空已有逻辑：`prepareForClose()` → `clearLoadedData()` → `results=[]`（`SearchView.swift:99-117`），挂在 `windowWillClose` hook 上。
- 移除自动翻页 `loadMoreIfNeeded` 的副作用？不移除——保留无害（`browseLimit` 已等于 total，`canAutoLoadMore` 里 `browseLimit < totalHistoryCount` 为 false，自然不再触发）。

> 说明：项目里没有独立"历史管理器"窗口，`SearchWindow`（标题 `searchHistory`，菜单栏 History header / 全局热键进入）就是浏览全部历史的入口。这次改造后它完全符合你说的"打开才加载全部、关闭即清空"。

## B 批：剩余长驻内存清理

### B1. 漏掉的第 3 个 CIContext
**文件**：`Screenshot/UI/Overlay/OverlayView.swift:4685`
`outlineGlowCIContext`（static let，上一轮优化漏了）改为 `_outlineGlowCIContext: CIContext?` + 计算属性 + `releaseOutlineGlowContext()`。在 `MemoryFootprintReclaimer.reclaimIfIdle/reclaimAfterScreenshot` 各加一行调用。量级 30-80MB。

### B2. VideoEditor 清理缩略图条
**文件**：`Screenshot/UI/Editor/VideoEditorWindowController.swift`（VideoEditorView.cleanup ~563 行）
`cleanup()` 末尾补 `thumbnailImages=[]; thumbnailStrip=nil; asset=nil; textRasterCache.removeAll(); effectsOverlay=nil`。当前靠 view 整体释放兜底，但名字暗示应清理大对象——显式置空抗未来改动。量级几十 MB。

### B3. ToolbarButtonView iconCache 改 NSCache
**文件**：`Screenshot/UI/Toolbar/ToolbarButtonView.swift:25`
`iconCache` 从无界 `[String:NSImage]` 改为 `NSCache<NSString,NSImage>` + `countLimit`，并把 key 里的颜色 RGB 量化到 16 级（避免取色器每个新颜色都永久驻留一条）。量级几~几十 MB。

### B4. FloatingThumbnail 兜底上限
**文件**：`Screenshot/Services/FloatingThumbnailPresenter.swift:18,85`
`controllers` 数组在 stacking 模式下加兜底上限（如最多 8 张，超过时移除最旧）。当前若用户把"自动消失"设为永不(`thumbnailAutoDismiss=0`)，每张 4K 截图 30-50MB 无限累积。
