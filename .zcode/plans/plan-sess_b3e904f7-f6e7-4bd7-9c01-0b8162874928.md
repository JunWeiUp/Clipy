## 修复截图模糊：导出丢失 Retina 原生像素

### 根因（已用事实验证）
实测自动保存的截图文件像素尺寸：`550x472`、`811x724`、`942x453` 等——这些都是**逻辑点（points）尺寸**，不是 Retina 原生像素。在 2x Retina 屏上，一张选区 550pt 的截图本应是 1100px，但实际只有 550px（正好少了一半），放大必然模糊。

**直接 bug 在 `ScreenshotImageProcessor.bestCGImage(from:)` 的 fallback 路径**（`ScreenshotImageProcessor.swift:240-243`）：
```swift
var rect = NSRect(origin: .zero, size: image.size)  // image.size = 逻辑点 550x472
if let cgImage = image.cgImage(forProposedRect: &rect, ...) {
    return cgImage  // ← 按逻辑点尺寸光栅化，把原生 1100x944 降采样成 550x472
}
```

**为什么走到 fallback**：捕获链路 `ScreenshotImageProcessor.fromCapture`（`:61`）返回 `NSImage(cgImage: 原生像素, size: 逻辑点)`——这种构造方式 NSImage 内部**只有一个裸 CGImage，没有 NSBitmapImageRep**。所以 `bestCGImage` 第一段循环（遍历 `image.representations` 找 NSBitmapImageRep）找不到，被迫走 fallback，而 fallback 用 `image.size`（逻辑点）作光栅化尺寸，原生 2x 像素被砍掉。

**影响范围**（同一根因的多处表现）：
- `renderFlattenedImage`（`AnnotationCanvasView.swift:610`）调 `bestCGImage(baseImage)` → 标注截图导出降采样
- `pngData`（`ScreenshotImageProcessor.swift:132`）调 `bestCGImage` → 所有保存的 PNG 降采样
- `ScreenshotExport.swift:14` 和 `ImageOCRService.swift:56` 用 `image.cgImage(forProposedRect: nil)` → pin/OCR 也拿低分辨率

### 修复策略：双管齐下根治

**改动一：`bestCGImage` 的 fallback 不再按逻辑点降采样**（`ScreenshotImageProcessor.swift:240-243`）
当 NSImage 没有 NSBitmapImageRep 时，尝试用**无尺寸限制**的方式取出原生 CGImage。把 `rect` 初始化为基于像素的真实尺寸而非 `image.size`：
- 优先尝试 `image.cgImage(forProposedRect:)` 但传一个以"可能的像素尺寸"初始化的 rect，或
- 更可靠：直接给 NSImage 的 fallback 路径补一个**临时 NSBitmapImageRep** 再取其 cgImage（这样能拿到原生像素）

具体实现：fallback 时用 `NSBitmapImageRep(cgImage: image.cgImage(forProposedRect: &infiniteRect))` 不行（仍会降采样）。正确做法是：**fallback 里用 image 内部能拿到的最大 CGImage**——通过先 `image.representations` 检查 `NSImageRep`（非 bitmap 的也跳过），然后用一个"不限尺寸"的 rect。实际上最稳的是：**给 fromCapture 产出的 NSImage 显式 addRepresentation(NSBitmapImageRep(cgImage: 原生cgImage))**，让 bestCGImage 第一段就命中。

**改动二（核心，最可靠）：`fromCapture` 给 NSImage 显式添加原生像素的 NSBitmapImageRep**（`ScreenshotImageProcessor.swift:51-62`）
```swift
static func fromCapture(_ cgImage: CGImage, logicalSize: NSSize, ...) -> NSImage {
    let image = NSImage(cgImage: cgImage, size: logicalSize)
    // 显式添加 bitmap rep，使后续 bestCGImage / cgImage(forProposedRect:)
    // 能直接取到原生像素，避免被 image.size（逻辑点）降采样。
    let rep = NSBitmapImageRep(cgImage: cgImage)
    rep.size = logicalSize
    image.addRepresentation(rep)
    return image
}
```
这样 bestCGImage 第一段循环就能命中原生像素 CGImage，所有下游（flatten/pngData/pin/OCR）都拿到全分辨率。

**改动三：`bestCGImage` 的 fallback 加防御性修复**（防止其他地方构造的裸 NSImage 也降采样）
把 fallback 的 rect 改为不限制像素：用 `image.cgImage(forProposedRect: &rect)` 前先尝试把 rect 设成足够大（或用 `hints: [NSImageRep.HintKey.interpolation: .none]` 路径，已有但 rect 仍是逻辑点）。最稳的防御：fallback 也用 NSBitmapImageRep 包一层取最大像素。

**改动四（防御）：`renderFlattenedImage` 的返回值**（`AnnotationCanvasView.swift:647`）
当前返回 `NSImage(cgImage: output, size: baseImage.size)` 又是裸 NSImage。改为同样 addRepresentation，保证 flatten 后的图再经 pngData 时不降采样。或更简单——把 pngData 的入口改为直接用已经拿到的 cgImage，绕过 bestCGImage。

### 验证方法（用事实验证，非纸上推理）
1. 构建后实际截一张图，用 `python3` 读 PNG header 的真实像素尺寸
2. 在 Retina 屏上选一个已知逻辑尺寸的区域（如 500pt），验证保存的 PNG 是 ~1000px（2x）而非 500px
3. `swiftc -typecheck` 编译通过

### 预期效果
- 截图保存的 PNG 恢复 Retina 原生像素（2x），放大后清晰
- 标注后的截图同样保持原生分辨率
- pin/OCR 也用原生分辨率
- 不影响历史预览的 1600px 降采样（那是显示优化，合理）

### 不在本次范围
- 不改捕获参数（`.best` + 原生 width/height 本就正确）
- 不改 PNG 编码（本就无损）
- 不改历史预览的 maxPixelSize（显示降采样是合理的内存优化）
- 不改缩略图尺寸（72/32/16 是列表图标，合理）
