修复 macOS 菜单栏"第一次打开抖动 / 字体布局跳动 / 有时无法选中"的问题。

## 根因
菜单在已打开状态下被异步链（设备扫描逐个回调、剪贴板变化、通知变化、refreshLanDevices 的 1.0s 二次刷新）反复触发 `removeAllItems()` + 全量重建（MenuController.swift:128-140, 153-156）。每次重建又重新发起所有缩略图/HTML 标题异步加载，叠加抖动；重建瞬间销毁正在 hover/展开的 item → 无法选中。Section header 用自定义 view + cancelTracking，重建时 trackingArea 要重建，偶发点击丢失。

## 方案（5 处改动，2 个文件）

### 改动 1（核心）：菜单打开期间禁止全量重建，改脏标记
MenuController.swift：
- 新增 `isMenuOpen`、`isMenuDirtyWhileOpen` 状态
- menuNeedsUpdate 进入设 isMenuOpen=true、清 dirty；menuDidClose 设 isMenuOpen=false，若 dirty 则 rebuildMenuContents 一次（保证下次/语言切换后最新）
- scheduleMenuUpdate 改为：菜单未打开直接 return；打开期间不 removeAllItems，仅置 dirty 并按触发源分流

### 改动 2：设备区实时增量更新（满足"实时追加但只更新设备区"）
MenuController.swift：
- Network section header item 与本机 IP item 打固定 tag，定位设备项区间
- onDevicesChanged 回调：菜单打开期间比较 menu 当前设备项 与 SyncManager.shared.availableDeviceEntries，仅对设备几行做 insertItem/removeItem/改 title，不动历史/片段/工具区
- refreshLanDevices 的 1.0s 二次刷新改走同样的设备区增量更新，不再 scheduleMenuUpdate

### 改动 3：缩略图/HTML 标题预占尺寸，消除跳动
MenuController.swift makeHistoryMenuItem：
- 图片项构造时先同步挂占位图标（SF Symbol photo，32pt），首次渲染即正确尺寸；异步缩略图回来替换 image 尺寸不变
- HTML 项保持现状（改动 1 后打开期间不再重建，其一次性标题替换影响已很小）

### 改动 4：启动预热首屏数据，消除第一次打开卡顿
ClipboardManager.swift init 末尾 loadHistory() 之后：
- 后台预热 fetchSummaries(limit: menuHistoryLimit)，结果丢弃（仅暖 SQLite 缓存页 + 缩略图磁盘缓存），不写入 recentSummaries，不改变打开时才正式加载的语义

### 改动 5：Section header 交互稳定性
改动 1 后菜单打开期间不再重建，section header view 对象在打开期间稳定，trackingArea 不再反复重建，自动修好。viewDidMoveToSuperview 的 menu-width 自适应保留。无需大改。

## 改动文件
- clipy_macos/Sources/App/MenuController.swift（改动 1/2/3/5）
- clipy_macos/Sources/Clipboard/ClipboardManager.swift（改动 4）

## 验证
- proxy && bash build_macos_app.sh 编译通过
- 手动：启动后第一次打开菜单无整体闪动/高度跳变；打开期间触发复制/通知/设备陆续上线——设备区平滑增删，其余区不动，正在 hover 的项不被打断、可正常选中
