## 二、剩余执行步骤（按 v2 第八节顺序 A → C → B）

### 步骤 1 · 完成 A-1 macOS 剩余 3 项

**1.1 改造 `sendSync`（L2210–2290）**
- 在方法体开头插入持久连接短路：若 `targetPeerId` 命中 `persistentConnection(for:)` 且连接存活，直接 `sendFrame(connection, data, …)`，`completion` 里失败则 `enqueuePendingSync` + `teardownPersistentConnection(peerId)`，**直接 return**，跳过新建 `NWConnection` 全段。
- 未命中分支保持现状（走 `performHandshake`，等价于建立持久连接）。
- 文件传输路径（`openBlockingConnection` L2160、`sendFrameBlocking`）**不在本步改造范围**（v2 明确 file 不走持久化，且需独立连接保证顺序）；保留现状。

**1.2 移除周期探活触发**
- 删除 `start()` 中 `startPeerPresenceProbing()`（L522）调用。
- 保留 `startPeerPresenceProbing`（L655）方法体，供 `refreshDiscovery()` 显式调用。
- 在线状态读取点（菜单/设备列表）改为以 `persistentConnections` 是否含 peerId 为准；具体读取点在实施时用 grep `discoveredPeers` 的 UI 暴露路径确认（复用现有 `notifyPeersChanged`）。

**1.3 POSIX 接受侧 keepalive**
- `posixArmClient`（L955）在 `fcntl(O_NONBLOCK)` 之后（L938 之后）追加：
  ```c
  int enable = 1; setsockopt(fd, SOL_SOCKET, SO_KEEPALIVE, &enable, sizeof(enable));
  // 可选：TCP_KEEPALIVE 设间隔（macOS 用 IPPROTO_TCP,TCP_KEEPALIVE）
  ```

**1.4 编译验证**：`swiftc -typecheck Sources/*.swift Sources/UI/*.swift`（参照 `build_macos_app.sh`）。

### 步骤 2 · A-2 Android `sync_manager.dart` 对称改造

**2.1 新增状态**（对标 macOS）：
```dart
final Map<String, Socket> _persistentConnections = {};   // peerId -> outbound
final Map<String, int> _reconnectBackoffSec = {};
static const int _keepaliveIdleSec = 60;
static const int _maxReconnectBackoffSec = 30;
```

**2.2 改造 `_performHandshake`（L1138–1173）**：握手成功（收到 hi 并 `_handleSyncMessage` 处理后，已知 peerId）时，**跳过 `finally` 的 destroy**，改为：
- 启用 keepalive：优先 `socket.setOption(SocketOption.levelTcpSocket, SocketOption.tcpKeepalive…)`；不可用则 `setRawOption(SOL_SOCKET, SO_KEEPALIVE)`（实施时确认目标 API level）。
- `_persistentConnections[peerId] = socket`；`_reconnectBackoffSec.remove(peerId)`。
- 启动接收循环：`unawaited(_handlePersistentReceive(socket, peerId))`（复用 `_handleConnection` 的分帧逻辑，`finally` 调 `_teardownPersistentConnection(peerId)` 而非裸 destroy）。
- 失败/超时分支维持 `socket.destroy()`。

**2.3 改造 `_sendSync`（L1683–1699）**：`_persistentConnections[peerId]` 存活 → `_writeFrame` 直写（不 close）；否则 `_performHandshake`（建持久连接）再写；失败维持现有重试/待投递路径。

**2.4 新增 `_teardownPersistentConnection` / `_scheduleReconnect`**：对称 macOS，指数退避 1→2→…→30s，复用 `_connectManualPeers`/`_scanSubnets`；网络恢复/页面打开时清退避立即重试。

**2.5 移除周期探活触发**：`start()` 中删除 `_startPeerPresenceProbing()`（L562）；`_stopPeerPresenceProbing` 保留。在线状态读 `_persistentConnections`。

**2.6 验证**：`flutter analyze` + `flutter build apk`。

### 步骤 5 · 改动 B 可靠投递
- B-1 新增 `message/ack` 类型（载荷 `{}`，用 `hash` 对齐）。旧端忽略未知类型，向后兼容。
- B-2 接收回 ack：macOS `processReceivedData` `text/plain` 分支（L1142）`handleRemoteSync` 后经 `reply` 闭包回 `message/ack`；Android `_handleSyncMessage`（L795）`text/plain` 经当前 socket 回写。`file/chunk` 在 `isLast` 回 ack。
- B-3 发送侧持久化 + 收 ack 删除：macOS 新增 `PendingSyncStore`（JSON，per-peer 上限 50、TTL 24h）；Android 泛化 `PendingSyncRepository`（SQLite）。连接（重）建立时 `flushPendingSync(forPeerId)` 重投。
- B-4 处理 ack：双端 `processReceivedData`/`_handleSyncMessage` 新增 `message/ack` 分支调 `handleMessageAck(hash)`。

## 三、决策与边界（沿用 v2，不新增）
- 纯局域网、不引云端；wake lock 保留（秒级硬约束）。
- 双向独立出站拓扑，每对设备 ≤2 条连接，不去重。
- file 不持久化字节，仅 `isLast` ack。
- `message/ack` 未识别时按 TTL 清理 + 重投，hash 去重幂等。
- 文件传输路径不改用持久连接（需独立连接保证顺序，v2 已明确）。
